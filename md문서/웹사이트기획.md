# SW 설계안: Invest REhearsal (MVP, 단순화版)

## 0. 확정 전제
- DB: SQLite (파일 1개, ORM 없음, `better-sqlite3`)
- Server: Node.js + Express (API + 정적 서빙 겸용, 서버만으로 개발 가능)
- Client: 프레임워크 없음 (Vanilla HTML/CSS/JS + `fetch`)
- 인증: 세션쿠키(`express-session`)
- 시세: 가상시세(랜덤워크) + 수수료 0원
- 게시판: 전체 작성 허용 + 보유자 `보유중` 뱃지

## 1. 아키텍처 (단순화)
- 단일 프로세스: `Express 서버 1개`
  - `REST API (/api/*)` + `정적 서빙 (/ -> /public/*.html)` 동시 담당
  - 별도 빌드/프론트 서버 없음
- 구조:
  - `Browser (vanilla JS, fetch + cookie) <-> Express <-> SQLite 파일(db.sqlite)`
- 서버만 개발 가능한 이유:
  - `express.static('public')`로 HTML/CSS/JS 서빙 → 클라이언트는 파일만 만들면 됨
  - API는 JSON만 반환, 화면 렌더링은 바닐라 JS가 `fetch` 후 `innerHTML`로 처리
  - 세션쿠키는 브라우저가 자동 전송 → 토큰 저장 코드 불필요

## 2. 기술 스택 / 패키지 (최소)
- `express`, `better-sqlite3`, `express-session` (+MVP는 `MemoryStore`, 운영시 `connect-sqlite3`)
- `bcryptjs` (비밀번호 해시), `express-rate-limit` (도배/로그인 방어, 선택)
- 개발: `node --watch src/server.js`
- 포트: `3000` 고정

## 3. 디렉토리 구조 (단순)
- `src/server.js`: 진입점, static + 세션 + 라우트 장착
- `src/db.js`: SQLite 연결 + 테이블 생성(`init.sql` 실행)
- `src/init.sql`: DDL 전체
- `src/middleware.js`: `requireLogin`, `requireAdmin`
- `src/routes/auth.js, stocks.js, trade.js, portfolio.js, board.js, admin.js`
- `src/price.js`: 가상시세 생성기
- `public/index.html, login.html, signup.html, dashboard.html, stocks.html, stock.html, portfolio.html, history.html, board.html, post.html, mypage.html, admin.html`
- `public/app.js, style.css`: 공용 fetch 래퍼 + CSS 1개

## 4. DB 설계 (SQLite, MVP용 축소 10개 테이블)

### 4.1. DDL 개요
- `users(id, email UNIQUE, pw_hash, nickname UNIQUE, role[USER/ADMIN], status, created_at)`
- `accounts(user_id PK/FK, cash, init_cash)` : 가입 시 `10,000,000` 고정 지급
- `stocks(code PK, name, cur_price, status[정상/정지], updated_at)` : 시드 10개로 시작
- `holdings(user_id, stock_code, qty, avg_price, PK(user_id,stock_code))`
- `transactions(id, user_id, stock_code, side[BUY/SELL], qty, price, pnl, created_at)`
  - 수수료 컬럼 제거(0원 확정으로 단순화), `pnl`은 SELL일 때만 기록
- `asset_history(user_id, date, total)` : 하루 1회 스냅샷, 그래프용으로 최소화
- `posts(id, stock_code FK, user_id FK, title, body, views, likes, status[정상/블라인드], created_at)`
- `comments(id, post_id FK, user_id FK, body, status, created_at)` : 대댓글 없음(1단 단순화)
- `notices(id, scope[전체/종목], stock_code?, title, body, pinned, by_admin, created_at)`
- `stock_events(id, stock_code, type[급등/급락/정지/배당], rate, status[예약/진행중/종료], reason, by_admin, start_at, end_at)` + `price_logs(id, stock_code, prev, next, cause, by_admin, created_at)`
  - `reports/sanctions/likes`는 MVP 제외 → 신고는 `posts.status=블라인드` + 관리자 삭제만으로 대체, 좋아요는 `likes` 카운트+쿠키 중복방지로 대체

### 4.2. 초기 데이터
- 관리자 1개 시드(`admin@invest.local / 변경필수`), 종목 10개, 현재가 고정 후 `price.js`가 변동

## 5. API 설계 (REST, JSON만, 총 22개 내외)

### 5.1. Auth (`/api/auth`)
- `POST /signup {email,pw,nickname}` → 계좌 생성
- `POST /login {email,pw}` → 세션 생성(`req.session.userId`)
- `POST /logout`, `GET /me`, `PUT /me {nickname,pw}`, `DELETE /me`

### 5.2. 종목/시세 (`/api/stocks`)
- `GET /stocks?q=` 목록, `GET /stocks/:code` 상세(현재가+보유여부+뱃지용)
- 가상시세 규칙(`src/price.js`, 1분마다):
  - `next = cur * (1 + rand(-0.02~0.02) + event_rate)` , 정지 종목 제외
  - 이벤트 진행중이면 `event_rate` 가산, 종료 시 원복 없음(로그만 남김)

### 5.3. 거래 (`/api/trade`)
- `POST /buy {code, qty}` : 현금 체크 → `holdings` upsert(평균단가 재계산) → `transactions` BUY → 현금 차감
- `POST /sell {code, qty}` : 보유 체크 → 현금 증가 → `transactions` SELL(`pnl=(sell-avg)*qty`) → 0주면 `holdings` 삭제
- 검증: `qty>=1 정수`, `status=정지` 종목 거래 차단, 시장가(`cur_price`) 단일가

### 5.4. 수익/내역 (`/api/portfolio`, `/api/history`)
- `GET /portfolio` → `{cash, stockVal, total, profit, rate, items:[{code,qty,avg,cur,pnl,rate}]}`
- `GET /history?type=&code=&from=&to=` 거래 목록, `GET /assets` 그래프용 스냅샷 목록

### 5.5. 게시판 (`/api/board`)
- `GET /posts?stock=&sort=최신/좋아요&q=`, `POST /posts {stock_code,title,body}`
- `GET /posts/:id (views+1)`, `PUT/DELETE /posts/:id (본인만)`
- `GET/POST /posts/:id/comments`, `DELETE /comments/:id (본인만)`
- `POST /posts/:id/like` (1인 1회, 세션ID 기준 메모리 체크로 단순화)
- 보유뱃지: 상세 조회 시 `holdings` 존재 여부로 `isHolder` 반환 → 클라가 뱃지 표시

### 5.6. 관리자 (`/api/admin`, `requireAdmin`)
- `GET /admin/summary` (가입자, 거래수, 신고대기→블라인드수, 진행중 이벤트)
- 게시판: `POST /notices`, `POST /posts/:id/blind|unblind`, `DELETE /posts/:id`, `GET /users`, `PUT /users/:id/stop`
- 이벤트: `POST /events {code,type,rate,start_at,end_at,reason}` → 즉시/예약, `POST /events/:id/cancel`, `POST /stocks/:code/price {price}` 직접조작(반드시 `price_logs` 기록)
- 조작 시 자동 공시: `notices`에 `[공시] 코드 사유` 자동 생성

## 6. 인증/권한 설계
- 세션: `cookie.httpOnly, maxAge 7일, sameSite=lax`
- 미들웨어:
  - `requireLogin`: 세션 없으면 `401`
  - `requireAdmin`: `users.role!=ADMIN` 이면 `403`, `/admin.html` 진입 전 `/api/auth/me`로 차단
- 비번: `bcryptjs.hash(10)`, 평문 저장 금지, 관리자 생성은 시드로만

## 7. 클라이언트 설계 (Vanilla, 프레임워크 없음)
- 공통: `app.js: api(path,method,body)` 래퍼가 `fetch(...,{credentials:'include'})` 처리, `401`이면 `login.html`로 이동
- 페이지별 JS 인라인 50줄 이내 원칙, 별도 라우터 없음 (HTML 1파일=1화면)
- 핵심 화면:
  - `stock.html`: 시세 표시 + 수량 입력 + 매수/매도 버튼 + 확인모달 + 종목 게시글 탭
  - `portfolio.html`: 요약 카드 4개 + 종목 테이블 + `canvas` 라인 1개(자산 추이)
  - `admin.html`: 탭 3개(이벤트생성/블라인드/유저정지)로 축소, 테이블+폼만

## 8. 예외/검증 (단순)
- 공용 에러 포맷: `{error:'CASH_LACK'|'HOLDING_LACK'|'NOT_FOUND'|'FORBIDDEN'}` + 클라 토스트 표시
- 도배 방지: `express-rate-limit (글쓰기 30초 1회)` 1줄로 대체, 금칙어 필터 MVP 제외
- 탈퇴: `users.status=탈퇴`, 글은 유지 + 닉네임 `탈퇴회원` 표시

## 9. MVP 개발 순서 (4단계)
- 1단계: Auth+Account+Static 서빙 (가입→로그인→대시보드 확인)
- 2단계: Stocks+Price+Trade+Portfolio (매수/매도→수익 확인)
- 3단계: Board+Comment+Like+뱃지
- 4단계: Admin(공지/블라인드/이벤트/조작로그)

## 10. 설계 제외 (2차)
- 지정가/예약/공매도, 신고함/제재이력 고도화, 대댓글, 이미지 업로드, CSV, OTP
