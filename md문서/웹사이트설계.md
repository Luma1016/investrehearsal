# 웹사이트 설계안: Invest REhearsal (MVP)

## 0. 개요 및 확정 전제
- 목표: MVP 단순 구현, server만으로 전체 개발/실행 가능
- DB: SQLite (파일 1개, ORM 없음, `better-sqlite3`) — 확정
- Server: Node.js + Express 단일서버 (API + 정적 서빙 겸용) — 확정 (2026-10-11 확인)
- Client: 웹프레임워크 없음 (Vanilla HTML/CSS/JS + `fetch`) — 확정
- 인증: 세션쿠키 (`express-session`, MemoryStore) — 확정
- 시세: 가상시세 (랜덤워크, 1분 주기, 수수료 0원) — 확정
- 포트: `3000` 고정, 실행: `node --watch src/server.js`

## 1. 아키텍처 (단순화)
- 단일 프로세스 구조:
  - `Browser (Vanilla JS, fetch + cookie) <-> Express (:3000) <-> SQLite (db.sqlite)`
- Express 역할:
  - `REST API (/api/*)` : JSON만 반환
  - `정적 서빙 (express.static('public'))` : `/ -> public/*.html`
  - 별도 빌드 / 프론트 서버 없음
- server만으로 개발 가능한 이유:
  1. HTML/CSS/JS는 `public/`에 파일만 두면 바로 서빙됨
  2. 화면 렌더링은 클라가 `fetch` 후 `innerHTML`로 처리, 서버는 JSON만 신경씀
  3. 세션쿠키는 브라우저 자동 전송 → 토큰 저장 코드 불필요
  4. 추후 프론트 분리 시에도 API 그대로 재사용 가능

## 2. 기술 스택 (최소)
- 필수: `express`, `better-sqlite3`, `express-session`, `bcryptjs`
- 선택: `express-rate-limit` (글쓰기 도배/로그인 방어), 운영 시 `connect-sqlite3`
- 공용: `public/app.js` (fetch 래퍼), `public/style.css` (CSS 1개)

## 3. 디렉토리 구조
- `src/server.js` : 진입점, static + 세션 + 라우트 장착
- `src/db.js` : SQLite 연결 + 테이블 생성
- `src/init.sql` : DDL 전체
- `src/middleware.js` : `requireLogin`, `requireAdmin`
- `src/routes/auth.js, stocks.js, trade.js, portfolio.js, board.js, admin.js`
- `src/price.js` : 가상시세 생성기 (1분 타이머)
- `public/` : `index.html, login.html, signup.html, dashboard.html, stocks.html, stock.html, portfolio.html, history.html, board.html, post.html, mypage.html, admin.html` + `app.js, style.css`

## 4. DB 설계 (SQLite, 10개 테이블로 축소)
- `users(id, email UNIQUE, pw_hash, nickname UNIQUE, role[USER/ADMIN], status, created_at)`
- `accounts(user_id PK/FK, cash, init_cash)` : 가입 시 `10,000,000` 고정 지급
- `stocks(code PK, name, cur_price, status[정상/정지], updated_at)` : 시드 10개
- `holdings(user_id, stock_code, qty, avg_price, PK(user_id,stock_code))`
- `transactions(id, user_id, stock_code, side[BUY/SELL], qty, price, pnl, created_at)` : 수수료 없음, `pnl`은 SELL만 기록
- `asset_history(user_id, date, total)` : 하루 1회 스냅샷, 그래프용
- `posts(id, stock_code FK, user_id FK, title, body, views, likes, status[정상/블라인드], created_at)`
- `comments(id, post_id FK, user_id FK, body, status, created_at)` : 대댓글 없음
- `notices(id, scope[전체/종목], stock_code, title, body, pinned, by_admin, created_at)`
- `stock_events(id, stock_code, type[급등/급락/정지/배당], rate, status[예약/진행중/종료], reason, by_admin, start_at, end_at)` + `price_logs(id, stock_code, prev, next, cause, by_admin, created_at)`
- 제외: `reports/sanctions/likes` 테이블 제외 → 블라인드 + `likes` 카운트 + 쿠키 중복방지로 대체
- 초기 데이터: 관리자 `admin@invest.local`, 종목 10개, `price.js`가 현재가 변동

## 5. API 설계 (REST, JSON, 22개 내외)
### 5.1 Auth `/api/auth`
- `POST /signup {email,pw,nickname}` → 계좌 생성
- `POST /login {email,pw}` → `req.session.userId` 생성
- `POST /logout`, `GET /me`, `PUT /me {nickname,pw}`, `DELETE /me`

### 5.2 종목/시세 `/api/stocks`
- `GET /stocks?q=` 목록, `GET /stocks/:code` 상세(현재가 + 보유뱃지용)
- 가상시세 규칙 (`price.js`, 1분마다):
  - `next = cur * (1 + rand(-0.02~0.02) + event_rate)`, 정지 종목 제외

### 5.3 거래 `/api/trade`
- `POST /buy {code, qty}` : 현금 체크 → 평균단가 재계산 upsert → BUY 기록 → 현금 차감
- `POST /sell {code, qty}` : 보유 체크 → 현금 증가 → SELL 기록 (`pnl=(sell-avg)*qty`) → 0주면 삭제
- 검증: `qty>=1 정수`, 시장가(`cur_price`) 단일가, 정지 종목 차단

### 5.4 수익/내역
- `GET /portfolio` → `{cash, stockVal, total, profit, rate, items:[{code,qty,avg,cur,pnl,rate}]}`
- `GET /history?type=&code=&from=&to=`, `GET /assets` (스냅샷 목록)

### 5.5 게시판 `/api/board`
- `GET /posts?stock=&sort=최신/좋아요&q=`, `POST /posts {stock_code,title,body}`
- `GET /posts/:id (views+1)`, `PUT/DELETE /posts/:id (본인만)`
- `GET/POST /posts/:id/comments`, `DELETE /comments/:id (본인만)`
- `POST /posts/:id/like` (세션 기준 1인 1회)
- 보유뱃지: 상세 조회 시 `isHolder` 반환 → 클라 표시

### 5.6 관리자 `/api/admin` (`requireAdmin`)
- `GET /admin/summary` (가입자, 거래수, 블라인드수, 진행중 이벤트)
- `POST /notices`, `POST /posts/:id/blind|unblind`, `DELETE /posts/:id`, `GET /users`, `PUT /users/:id/stop`
- `POST /events {code,type,rate,start_at,end_at,reason}`, `POST /events/:id/cancel`, `POST /stocks/:code/price {price}` (반드시 `price_logs` 기록 + `notices` 자동 공시)

## 6. 인증/권한
- 쿠키: `httpOnly, maxAge 7일, sameSite=lax`
- `requireLogin` : 세션 없으면 `401`
- `requireAdmin` : `role!=ADMIN` 이면 `403`, `/admin.html` 진입 전 `/api/auth/me` 체크
- 비번: `bcryptjs.hash(10)`, 평문 저장 금지

## 7. 클라이언트 설계 (Vanilla)
- 공용 `api(path,method,body)` : `fetch(...,{credentials:'include'})`, `401`이면 `login.html` 이동
- 원칙: HTML 1파일=1화면, 라우터 없음, 페이지 JS 50줄 이내
- 핵심:
  - `stock.html` : 시세 + 수량 + 매수/매도 + 확인모달 + 종목글 탭
  - `portfolio.html` : 요약카드 4개 + 테이블 + `canvas` 라인 1개
  - `admin.html` : 탭 3개 (이벤트생성/블라인드/유저정지)

## 8. 예외/검증
- 에러 포맷: `{error:'CASH_LACK'|'HOLDING_LACK'|'NOT_FOUND'|'FORBIDDEN'}` + 토스트 표시
- 도배 방지: `express-rate-limit (글쓰기 30초 1회)`, 금칙어 MVP 제외
- 탈퇴: `users.status=탈퇴`, 글 유지 + `탈퇴회원` 표시

## 9. 개발 순서 (4단계)
- 1단계: Auth + Account + Static 서빙
- 2단계: Stocks + Price + Trade + Portfolio
- 3단계: Board + Comment + Like + 뱃지
- 4단계: Admin (공지/블라인드/이벤트/조작로그)
